# 自動検出・吸引とWebログの実行版

使用者提供の実行プログラムを `firmware/deneuve_runtime/deneuve_runtime.ino` に収録しました。18点の受光、左右LED差分、小さく変化する影の候補判定、Webログ、サーボによる吸引シーケンスを含みます。実装があることと実機で蚊を検出・捕獲できることは区別し、検出性能と捕獲動作は未検証です。

## 提供コードからの変更

- Arduinoの自動生成プロトタイプより先に型を読めるよう、`DetectionResult` の定義を `DetectionResult.h` に移しました。原文はこの型の未定義エラーでコンパイルできませんでした。
- Wi-Fi認証情報を `secrets.h` から読む構成にしました。ファイルがない場合はサンプルのプレースホルダーでコンパイルします。

検出アルゴリズム・しきい値・点灯周期・サーボシーケンスは原文を維持しています。

## 開始手順

1. Arduino IDEで `firmware/deneuve_runtime/deneuve_runtime.ino` を開きます。
2. ESP32コア3.3.11とESP32Servo 3.2.1を使用します。Flash Sizeは16MB、PSRAMはOPI PSRAM（容量8MB）。USB設定は使用端子に合わせます。
3. 同じフォルダーの `secrets.example.h` を `secrets.h` にコピーし、SSIDとパスワードを手元で設定します。`secrets.h` はGit管理対象外です。実際の認証情報を `.ino` やサンプルへ書き込まないでください。
4. [配線仕様](./hardware.md)を確認します。起動時にサーボが待機角へ動き、校正後は検出条件を満たすと自動でプッシュ動作を開始するコードです。まずサーボが掃除機ボタンに接触しない状態で検出ログを確認し、取り付けて試す際は掃除機の停止状態を確認します。
5. 書き込み後、シリアルモニタを115200 baudで開きます。Wi-Fi接続後に表示される `Open: http://...` のIPアドレスを、ESP32と通信できる同じLAN内のブラウザーで開きます。
6. 光路を遮らない状態で80回の基準値校正が終わり、`Mosquito trap ready` が表示されるのを待ちます。

Wi-Fi設定が未入力・誤りの場合、接続待ちから進みません。この版に接続タイムアウトやオフライン開始機能はありません。

## 検出処理

消灯→左LED→右LEDの順に、18点を各3回のADC平均で読み取ります。信号は `背景値−点灯値`（負値は0）。各LEDの基準値に対する信号低下率を求め、左右の低下率の大きい方を各点の影の強さとして採用します。

候補条件は次のすべてです。

| 指標 | コードの条件 |
| --- | --- |
| 有効点 | 影の強さが0.15超、または局所コントラストが0.08超 |
| 有効点数 | 1〜8点 |
| 有効点の影の総量 | 0.25以上 |
| 最大局所コントラスト | 0.08以上 |
| 前フレームからの変化量の合計 | 0.08以上 |
| 連続候補フレーム | 2回で検出イベント |

これは特徴量に基づく候補判定であり、蚊の種類や物体の同一性を認識するものではありません。左右の画像を最大値で合成しており、視差からの距離・奥行き推定は実装していません。

### 配列座標の仮定

コードはPT1〜PT6を上段、PT7〜PT12を中段、PT13〜PT18を下段とし、中段のx座標を5ずらした千鳥配置を仮定します。x方向の刻みは10、y座標は0・10・20です。単位と実物寸法は未確定で、この座標をmmなどの実測値と扱いません。現在報告されている「横6個×3列」の実配置・配線順と照合が必要です。

近傍判定は座標の距離の二乗125以下を使用します。実配置が異なると、局所コントラストと重心の解釈が変わります。

## サーボのシーケンス

停止している掃除機に対して、以下を実行します。

```text
1回目押下250ms → 解放300ms
2回目押下250ms → 解放300ms → 強吸引待機3000ms
3回目押下250ms → 解放300ms → IDLE
```

待機角20°・押下角65°、GPIO16、50Hzです。`millis()` による状態遷移で動かします。再トリガー禁止は前回のシーケンス開始から8000msで、起動直後も稼働時間8000ms未満は開始しません。吸引中も検出・ログ処理は続きますが、新しいシーケンスは開始しません。

ログの検出件数は吸引回数・捕獲数ではありません。同じ影で複数イベントが出る場合や、再トリガー禁止中に検出ログだけが増える場合があります。掃除機の状態・ボタンの押下成功を確認するセンサーはありません。

## Webログ

- `/`：3秒ごとにページ更新。起動後の秒数、制御シーケンスのBUSY/IDLE、最新50件を表示。
- `/json`：同じログをJSONで返す。
- 記録項目：起動後時刻 `timeMs`、有効点数、影の総量、変化量、局所コントラスト、重心 `cx` / `cy`。
- ログはRAM内のリングバッファで、再起動すると消えます。

GitHub Pagesは開発文書です。ライブのログ画面はESP32上のHTTPサーバーで提供し、GitHub Pagesへ転送する処理はありません。認証機能はないため、アクセス可能なLAN内で利用します。画面のIDLEは制御シーケンスの状態で、掃除機が実際に停止したことの確認ではありません。

## 実機検証前の確認点

- 校正信号が1未満なら1に補正します。信号の弱い点・未接続点でも大きな影として扱われる可能性があります。点ごとの信号有効性を判定する処理は未実装です。
- 基準値の追従停止条件は候補判定のみです。静止物体や広い遮光など、候補条件を満たさない遮光が基準値へ取り込まれる可能性があります。
- 100kΩの受光回路で、消灯後150µs・点灯後250µs・MUX切替後8µsの待ち時間が十分かは未検証です。個別テスト版の待ち時間とも異なります。
- `motion` は全点の影の強さの変化量の合計で、速度や移動方向ではありません。Web応答や走査時間によりフレーム間隔も変わります。
- サーボ更新はメインループで行うため、HTTP処理や光学走査の時間だけ状態遷移が遅れる場合があります。実時間の保証はありません。
- 停止・再校正・自動吸引の有効／無効を切り替える操作はありません。手動操作・押下失敗・リセット後の掃除機状態との再同期も未実装です。

コンパイル検証はGPIO配線、メモリ実容量、光学応答、Wi-Fi接続、Web表示、サーボ押下や捕獲性能の実機検証を代替しません。
