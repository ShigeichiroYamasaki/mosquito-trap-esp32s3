# 誘引・検出・吸引の機構

現時点のシステム名は **Deneuve 2** です。

このページでは、Deneuve 2の誘引・検出・吸引の設計を説明します。誘引効果、蚊の影の検出性能、捕獲率は未検証で、個別操作用の[テスト版](./hardware-test.md)を保存していますが、[実行版](./runtime.md)には自動検出・吸引制御も収録しています。実機での統合動作は未検証です。

## 人工皮膚の定義

**人間が半日以上履いた靴下を、36°C のヒーターで加温したものを「人工皮膚」と呼びます。** 靴下の匂いと加温によって人間の存在・体温を模倣し、蚊を近づける構想です。

36°C は指定されたヒーターの温度です。実装時には、温度センサーの位置と、ヒーター温度・靴下表面温度の関係を確認します。靴下表面がすでに 36°C に制御できているという意味ではありません。

## ケースと呼吸を模した拡散

CO₂ 噴出口とヒーター付き人工皮膚を **10cm 角のケース**に格納し、ケースの下面に **5V ファン**を取り付けます。ファンで CO₂ と靴下の匂いを **4〜6秒間隔**で拡散し、動物の呼吸を模したリズムを作る設計です。

ファンの間欠動作は **555 タイマー IC**を使って実装します。ESP32-S3 のソフトウェアでこの周期を生成する仕様ではなく、555 のタイマー回路として設計します。ファン用電源は 5V とし、555 の型番・電源条件・負荷駆動回路は部品選定時に具体化します。

- ケースは 10cm × 10cm の寸法指定として記録し、高さと内寸・外寸の区別は未確定です。
- 「4〜6秒間隔」の ON 時間・OFF 時間の内訳と、固定周期を調整するのか周期を変動させるのかは未確定です。
- 下面のファンの送風方向、吸気口・排気口、CO₂ 噴出口と人工皮膚の配置は今後設計します。
- ケース内に格納する指定は CO₂ の**噴出口**と人工皮膚です。重曹・クエン酸の反応容器の配置は未確定です。

CO₂濃度に断続的な変化を作ることを目指して間欠拡散を採用しています。[研究論文と濃度変動を設ける理由](./index.md#co2-rhythm)を参照してください。4〜6秒間隔は実験で評価する仮設定です。

このファンは誘引源の拡散用です。捕獲時の吸引は、別の掃除機とサーボで行います。呼吸を模した拡散による誘引効果は未検証です。

[6時間分の材料量・クエン酸の滴下速度とシステム図](./index.md#co2-six-hours)はトップページに掲載しています。

## 動作の流れ

1. **CO₂ で誘引する。** 重曹とクエン酸で発生させた CO₂ を利用します。
2. **人工皮膚に近づける。** 半日以上履いた靴下の匂いと、36°C のヒーターによる加温を組み合わせます。10cm 角のケース下面の 5V ファンを 555 タイマーで間欠動作させ、CO₂ と匂いを 4〜6秒間隔で拡散します。
3. **接近を影として検出する。** 人工皮膚に接近する蚊が赤外線 LED の光を遮る変化を、赤外線受光素子で読み取ります。
4. **影の動きを認識する。** トンボの複眼を模した受光素子の配列から、照射元の LED ごとの影の違いと遮光位置の時間変化を取得する方針です。
5. **吸い込む。** ESP32-S3 がサーボモータを動かし、停止中の掃除機のプッシュボタンを2回押して強吸引にします。吸引後にもう1回押して停止させます。

これは狙う誘引・捕獲の順序です。拡散ファンの間欠動作は指定されていますが、CO₂ の発生・供給そのものやヒーターを同じ周期で ON/OFF する仕様は指定されていません。

```text
重曹 + クエン酸 → CO₂ 噴出口 ┐
                             ├ 10cm 角のケース
靴下 + 36°C ヒーター → 人工皮膚 ┘
                             ↓ ケース下面
555 タイマー → 駆動回路 → 5V 拡散ファン
                             ↓ 4〜6秒間隔で CO₂ と匂いを拡散
                            蚊を誘引・接近
赤外線 LED 2個（交互点灯）→ 蚊による遮光 → 複眼状の赤外線受光素子配列
                            ↓ 各受光素子の時系列データ
                       ESP32-S3
                            ↓ 接近判定
                      サーボモータ
                            ↓ プッシュボタンを2回押す
                         掃除機 → 強吸引 → さらに1回押して停止
```

## 複眼方式：18点から影の振る舞いを捉える

発光部は940nmの赤外線LED 2個、受光部はMoechando 940nm・5mmのフォトトランジスタ18個です。受光配列は6個×3段で、中央段を半ピッチずらす設計です。PT1〜6が上段、PT7〜12が中段、PT13〜18が下段に対応します。実際の間隔・配線順を照合して使います。

最大の特徴は「蚊そのもの」の形を識別せず、「蚊らしい影の振る舞い」を検出することです。小さい・局所的に暗い・連続して移動する・短時間で消える、という条件を組み合わせます。トンボの複眼やSTMDに着想を得た設計であり、同等の生物機構や識別性能を実証したものではありません。

![同じ照明で影の移動を確認し、消失前に吸引を開始する](/detection/tracking-capture.svg)

左右の照明は独立に追跡し、各照明の時間方向の移動を調べます。蚊以外の小さな物体も条件を満たし得るため、イベントは「捕獲候補」として扱います。

## 3相フレームと初期校正

1フレームは全LED OFF → 左LEDのみON → 右LEDのみONです。各相で同じ18点を読み、`leftSignal = OFF − LeftON`、`rightSignal = OFF − RightON`を求めます。

![3相フレームと左右の背景差分](/detection/frame.svg)

LEDの集光によって中央と周辺の受光量が異なるため、光路を空けて80フレームの初期校正を行います。左右別・点別の基準値に対する低下率を影として扱い、弱すぎる点、飽和した点、不安定な点を除外します。差分自体が影なしの明るさを示すのではなく、校正で得た値が影なしの基準です。

LEDから受光部まで約10cm。光量補正は実際の照射むらや感度不足を解消しないため、各点の有効性も確認します。LED・MUXの待ち時間とフレーム周期は実測して調整します。現在の待ち時間では数msの通過を保証できません。

## 次期：左右照明による影の視差

![左右から照らすと同じ物体の影が受光面の別位置に現れる](/detection/parallax.svg)

左右それぞれから照らした18点の影パターンを比較し、奥行きの手掛かりを得る計画です。これは両眼カメラの画像ではなく、同じ受光面に投影した影です。LED間隔、受光部の実寸と位置、左右の取得時間差による移動を考慮する必要があります。

左右交互照射と各照明の追跡は実装済みですが、視差による距離推定・誤検知除去は未実装です。詳しい判定条件と検証方法は[複眼方式の設計](./detection-design.md)にまとめています。

## 掃除機の選定

現在はDCモーターのコンパクトな掃除機を採用します。当初は小型であることと、USBケーブルを使った給電・充電によって配線を単純にできることを重視しました。ただし、USB給電中の連続運転可否は機種仕様の確認が必要です。

![採用する掃除機の参考写真（使用者提供）](https://m.media-amazon.com/images/I/61AI7mS2TOL._AC_SL1500_.jpg)

写真は使用者提供の商品画像です。メーカー・型番・定格電力・吸引性能は未記録です。

システム全体では実際に交流電源ケーブルを使用するため、将来は吸引性能を重視し、AC電源のハンディ掃除機への変更も検討します。現時点では候補方針であり、変更は未実施です。交流／直流という分類だけで吸引力を断定せず、吸込口での風量・負圧、起動遅延、サイズ、騒音、捕獲率を機種ごとに比較します。

**モーターや内部電気回路は改造せず、外側のスイッチをサーボモーターで押して操作します。** AC掃除機に変更する場合もこの方針とし、スイッチの形・押下力・運転状態の切り替わり方を確認して、サーボの機構と制御を合わせます。

## 掃除機のプッシュボタンと捕獲シーケンス

現在のDC掃除機はタクトスイッチ式のプッシュボタン型で、使用者によると **停止 → 弱吸引 → 強吸引 → 停止** の順に、1回押すたびに状態が切り替わります。

| 停止状態からの押下回数 | 掃除機の状態 |
| --- | --- |
| 0回 | 停止 |
| 1回 | 弱吸引 |
| 2回 | 強吸引 |
| 3回 | 停止 |

この3段階の切り替えは現在の掃除機の仕様です。将来のAC掃除機でも同じ挙動になるとは限りません。

捕獲候補を検出したときの操作シーケンスは次のとおりです。

1. **停止状態から開始**する。
2. サーボでボタンを押して離す（1回目：弱吸引）。
3. サーボで再びボタンを押して離す（2回目：強吸引）。
4. 強吸引で蚊を吸い込む。
5. 吸引後にサーボでもう1回押して離す（3回目：停止）。
6. 次の検出に備えて待機する。

```text
停止・検出待ち
    ↓ 蚊を検出
1回プッシュ → 弱吸引
    ↓
2回目のプッシュ → 強吸引
    ↓ 吸引後
3回目のプッシュ → 停止・待機
```

1回のプッシュは「押下してから解放する」動作とし、2回のプッシュの間にもボタンを解放します。押し続けることで吸引を維持する方式ではなく、押す回数で運転状態を切り替える方式です。

**現在の制御と残る課題**：このシーケンスは開始時に掃除機が停止していることを前提とします。吸引動作中の再検出で追加のプッシュが混入しないよう、検出待ちと捕獲処理の状態を分けます。手動操作、押下の失敗、ESP32-S3 の再起動などで実際の状態と押下回数がずれた場合の確認・復帰方法は未確定です。ボタンの解放だけでは停止を保証できないため、停止状態を確認する方法も実機で検討します。

実行版は待機角20°・押下角65°、押下250ms・解放300msを2回、強吸引待機3000ms、押下250ms・解放300msを1回としています。物理的な押下成功・捕獲成功は未検証です。

起動時は自動吸引無効（サーボは待機角へ移動）。シリアルの `a` で有効化、`d` で新規吸引を無効化します。進行中のシーケンスは停止押下まで続けます。影の消失確認と2回押下で起動が遅れるため、検出数と捕獲数を分けて評価します。[実行版の操作](./runtime.md)を参照してください。
