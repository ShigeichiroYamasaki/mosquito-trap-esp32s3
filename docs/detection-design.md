# 複眼方式の設計

Deneuve 2（ドヌーブ2）は「蚊そのもの」ではなく「蚊らしい影の振る舞い」を捕獲候補として検出する。トンボの複眼と小型移動物体検出（STMD）から着想を得た設計であり、生物の回路の再現や蚊の種の識別を実証したものではない。

## 全体構成

CO2（重曹とクエン酸）・半日以上履いた靴下の匂い・36℃の人工皮膚で誘引する。10cm角のケース下面の5Vファンを555タイマーで4〜6秒間隔に駆動する誘引部と、ESP32-S3による検出・サーボ制御部を分ける。ファン、ヒーターは実行プログラムの制御対象外。

検出部はFreenove ESP32-S3 Board Lite（Flash 16MB / OPI PSRAM 8MB）、940nm LED 2個、100kΩ負荷のフォトトランジスタ18個、CD74HC4067 2個。光路は約10cm。940nmを採用するが、蚊への行動影響や不可視性は未検証。

```text
OFF / 左ON / 右ON → 18点ずつ取得 → 背景差分
 → 左右別の校正・品質判定 → 正規化した影
 → 小ささ・局所性・隣接した移動・短い通過の判定
 → 捕獲候補ログ → 有効化されていれば2回押下→吸引→1回押下
```

## 3相フレーム

![OFF・左ON・右ONの順次取得と背景差分](/detection/frame.svg)

[図を拡大表示](/detection/frame.svg)

|相|左LED|右LED|取得|
|---|---|---|---|
|0|OFF|OFF|off[18]|
|1|ON|OFF|leftOn[18]|
|2|OFF|ON|rightOn[18]|

各相でLED切り替え後の待機、MUX選択、待機、最初のADC値の破棄、3サンプル平均を行う。フレーム終了時は両LED消灯。

```text
leftSignal[i]  = off[i] - leftOn[i]
rightSignal[i] = off[i] - rightOn[i]
shadow[l][i]  = 1 - signal[l][i] / baseline[l][i]
```

ADC値は明るいほど低い。差分はその時点のLEDによる受光量の指標で、影なしの基準は初期校正から得る。負の差分は保持し、異常の診断に使う。判定用shadowだけ0〜1に制限する。ADC生値の差分は物理的な光量や照度の測定ではない。

3相を同時には取得できない。背景光のちらつきや物体の移動は差分に混ざる。[EspressifのADC説明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/adc/index.html)でもoneshotは1チャンネルずつの取得である。本実装は走査時間、開始間隔、3相の読取開始オフセットをマイクロ秒で記録し、`/json`で表示する。点ごとの時刻保存・リアルタイム保証は未実装。

仮設定はLED切替後2000µs、MUX切替後50µs。3相のLED待機だけで6msを要するため、現設定で数msの通過を保証できない。100kΩ回路の整定を測定した上で短縮を検討する。対象通過時間3〜300msは調整用の仮定で、実測した蚊の分布ではない。

## 初期キャリブレーション

![受光量の場所による違いを基準比で正規化し、不良な測定点を除外](/detection/calibration.svg)

[図を拡大表示](/detection/calibration.svg)

遮蔽物のない状態で80フレーム取得。左右×18点について背景差分の平均と標準偏差を計算する。レンズ中央と周辺の照射差、素子の個体差を基準比で補正する。

仮の有効条件は、平均40 ADC count以上、標準偏差が平均の10%以下、校正中の全相でADC値が20より大きく4075未満。条件を満たさない照明・点は無効にし、割り算と検出から除く。各照明で12点以上有効であることを動作条件とする。この有効点数は全面の検出範囲を保証せず、無効点の位置も確認する。

OFFが上限に張り付くと背景差分が歪むため、この版では無効扱いとする。現物で多発する場合は、負荷抵抗・光量・ADC入力範囲を再調整する。補正で受光不足や飽和を解消できない。

校正はシリアルCSVとWeb表で確認する。基準値は固定し、静止した靴下や遮蔽物を背景として学習させない。温度や背景条件が変わった場合は、光路を空けて手動再校正する。自動追従は未実装。

## 局所コントラスト

局所コントラストは、注目する受光点の影が周囲に比べてどれだけ強いかを表す。

```text
局所コントラスト = 影中心 − 周辺平均

contrast[l][i] = shadow[l][i] − mean(shadow[l][j])
                                      j：iの有効な隣接点
```

「影中心」は注目している受光点であり、物体の中心位置が既知という意味ではない。入力はADC生値ではなく、左右別に校正した影の強さ `shadow`（0〜1、大きいほど暗い影）を使う。周辺平均には中心自身を含めない。

|例|中心の影|周辺の平均|局所コントラスト|
|---|---|---|---|
|局所的な影|0.60|0.10|0.50|
|全体が同じように暗い|0.60|0.60|0.00|
|中心より周囲の影が強い|0.10|0.60|−0.50|

画像処理のラプラシアンと同様に、中心と周囲の差から空間的な変化を強調する処理である。等間隔の上下左右4近傍なら、一般的な離散ラプラシアン `周辺4点の和 − 4 × 中心` に対し、この式は符号を反転して4で割ったものになる。[OpenCV：ラプラシアンの説明](https://docs.opencv.org/4.12.0/d5/db5/tutorial_laplace_operator.html)

本システムは千鳥配列なので、正方格子の3×3フィルターをそのまま適用せず、受光点の隣接関係で計算する。現行コードはピッチ単位の距離の二乗が1.26以下の点を近傍とし、校正で無効になった点は除く。端でも存在する有効近傍だけで平均し、有効近傍がない点のコントラストは0とする。

左右の照明ごとに計算し、最大局所コントラスト0.08以上を候補条件の一つとする（仮設定）。局所コントラストだけでは、物体の縁やノイズも反応するため、影の小ささ・まとまり・時間的な移動と組み合わせる。広い影の内部では値が小さくなるが、その縁まで除去できるわけではない。

## 影の振る舞いを追跡する

**捕獲開始の方針：影が見えている間に連続した移動を確認し、消失を待たず吸引を開始する。** 消失は追跡終了として記録し、短時間の通過だったかを事後評価する。以下の図はこの方針を示す。現行コードは消失時にイベントを確定する実装であり、下表はその実装条件を記載している。消失前の吸引開始へのコード修正は未実施。

PT1〜6が上段、PT7〜12が中段、PT13〜18が下段。中段は半ピッチ右へずらす。座標は受光素子のピッチ単位であり、mmではない。

```text
○ ○ ○ ○ ○ ○
 ○ ○ ○ ○ ○ ○
○ ○ ○ ○ ○ ○
```

左右は独立して追跡する。左右の最大値合成は診断ログのみで使い、照射切替による影のずれを時間的な移動と数えない。

|判定|仮設定|
|---|---|
|小さな影|shadow > 0.15の点が1〜4個|
|まとまり|有効点が隣接関係で一つにつながる|
|十分な変化|有効点のshadow合計 ≥ 0.25|
|局所性|隣接点平均との差の最大 ≥ 0.08|
|時間の連続|3フレーム以上、間隔50ms以下|
|移動の連続|重心の1ステップ移動 ≤ 1.5ピッチ|
|移動量|開始重心から最大0.25ピッチ以上|
|一過性|影が消えた時点で開始から3〜300ms|

消失を確認して初めて1イベントにする。広い影、離れた影、飛び移り、長い滞留はクリアになるまで再判定しない。同じ場所の明滅だけでは移動条件を満たさない。ただし重心は影の形・光量でも変わるため、物体の同一性や蚊であることを保証しない。左右それぞれが別時刻に消えると同じ物体から2イベントになり得る。捕獲シーケンスには8秒の再開始制限がある。

**消失確認には捕獲開始が遅れる代償がある。** さらに2回押下には強吸引になるまで約0.8〜1.1秒かかる。実際の通過位置と吸入口の配置、サーボの応答を測り、捕獲率が低ければ「移動確認時の早期起動」と「後から一過性を検証するログ」を分離する。その最適化は未実装。

## 吸引制御

起動時は自動吸引無効。シリアルの`a`で有効、`d`で無効、無効かつ待機中の`c`で再校正する。起動時にはサーボが待機角へ動く。掃除機の物理状態は検知できないため、`a`を送る前に掃除機が停止していることを確認する。

吸引シーケンス：押下250ms・解放300msを2回、吸引待機3000ms、押下250ms・解放300msを1回。`d`は新規起動を抑止し、進行中のシーケンスは最後の停止押下まで続ける。ESP32再起動や押下失敗では停止を保証しない。吸引中は追跡をリセットする。

Wi-Fi接続待ちは10秒で打ち切り、接続できなくてもシリアルと検出を継続する。Web処理による遅延があり、サーボ制御の厳密な時間保証はない。

## 次期：左右照明による影の視差

![左右の光源位置により同じ受光面で影がずれる概念図](/detection/parallax.svg)

[図を拡大表示](/detection/parallax.svg)

2個のLEDと同じ受光面を使うので、「両眼から見た画像」ではなく「左右から照らした18点の影」である。左右の対応する影の重心差、幅、強さから奥行きの手掛かりを得る。現在は視差による距離推定・候補棄却を実装していない。

将来の処理にはLED間隔、受光面との距離、18点の実位置の測定と、既知位置の遮蔽物による校正が必要。左右の取得時刻差に伴う移動を同じ照明の前後フレームから補間し、対応が曖昧なら距離を決めない。18点でどの程度の精度が得られるかは実測する。36点化ではMUXチャンネルも32を超えるため、追加MUXまたは取得回路の変更が必要。

## 検証手順と完了条件

1. [光学測定版](./optical-measure.md)で、遮蔽物なし・位置を変えた遮蔽物・背景照明変化を収集する。測定版は比較用の4相（OFF/左/OFF/右）で取得しており、実行版の3相とは別。
2. 実行版で左右各点の校正品質とフレーム周期を確認。既知位置で影がどの点に出るか配線順も照合する。
3. 小物体の通過、静止物体、広い遮光、靴下・ファンの揺れ、室内照明の変化を記録し、候補の検出率・誤検出回数/時間・遅延を比較する。
4. 実際の蚊について、通過数・候補数・吸引開始数・捕獲数を別々に記録する。真の通過を確認する独立した観察が必要。

ソフトウェアテストは校正の無効化、移動・静止・飛び移り・長い滞留・広域遮光・時刻オーバーフローを確認する。実機の光学応答、捕獲率、STMDとの同等性は未検証。
